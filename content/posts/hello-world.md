这是本站的第一篇文章。我把它当作一篇「施工日志」来写——记录这个博客是怎么搭起来的，也顺便讲讲我为什么做了这些选择。

## 为什么用 Hugo 而不是别的

在动手之前，我在几套方案之间犹豫过：

1. **纯 HTML**：最简单，上传即可用，但每写一篇文章都要复制一遍模板，内容一多就难以维护；
2. **Jekyll**：GitHub Pages 原生支持，但自定义主题受插件白名单限制，调样式时束手束脚；
3. **Hugo**：Go 语言编写、单二进制、构建速度快，内容用 Markdown 管理，模板完全自由。

最终我选择了 Hugo。理由很简单：它既保留了「内容与样式分离」的长期可维护性，又不需要在本地装一整套语言环境——只要一个 `hugo` 命令就够了。

> 一个直觉上的判断标准：如果你的博客未来会长出很多文章、想专注写作本身，静态站点生成器比纯手写 HTML 更适合；如果你只是想要一张名片页，纯 HTML 反而更省事。

## 目录结构一览

Hugo 项目的目录比想象中清爽：

```text
.
├── content/posts/   # 文章全部放在这里，Markdown 格式
├── layouts/         # 页面模板（首页 / 文章页 / 列表页）
├── static/          # 样式、脚本、图片等静态资源
└── hugo.toml        # 站点配置，个性化信息都集中在此
```

日常写文章时，我几乎只碰 `content/posts/` 这一个目录；改昵称、换头像、换首页背景图，则只需要编辑 `hugo.toml` 里的参数。

## 文章怎么写：Front Matter 约定

每篇文章的开头有一段 YAML 元信息，用来告诉模板「这篇文章长什么样」：

```yaml
---
title: '文章标题'
date: 2026-09-01
tags: [Hugo, 随笔]
description: '列表页展示的一句话摘要'
cover: '/img/covers/cover-hello.svg'
---
```

| 字段 | 作用 |
| --- | --- |
| `title` | 文章标题，同时会出现在浏览器标签页 |
| `date` | 发布日期，决定列表排序 |
| `tags` | 标签，会渲染成圆角小胶囊 |
| `description` | 摘要，显示在首页卡片上，也用于 SEO |
| `cover` | 封面图路径，留空则使用默认封面 |

## 部署：推上去就完事

仓库里放了一个 GitHub Actions 工作流（`.github/workflows/hugo.yaml`），流程非常简单：

```bash
git add .
git commit -m "新的文章"
git push origin main
```

推送后 Actions 会自动用 Hugo 构建站点并发布到 GitHub Pages。唯一需要手动做的一次性设置，是在仓库的 **Settings → Pages** 里把发布来源选为「GitHub Actions」。

## 设计上的小心思

整套界面遵循 Material Design 3 的明暗双主题设计令牌（颜色、圆角、阴影都抽成了 CSS 变量）。有几个实现细节我很喜欢：

- 首页首屏图中央只有一行字幕，且字幕颜色使用 `mix-blend-mode: difference`，会自动与背景像素取反——以后换任何背景图都不用重新调色；
- 向下滚动时右下角浮现「搜索 / 深浅色切换 / 回到顶部」三个按钮，搜索按钮悬停时会向左展开成输入框；
- 文章页采用左 30% 右 70% 的分栏，左侧固定展示封面、标题、作者与操作按钮，右侧专心阅读。
